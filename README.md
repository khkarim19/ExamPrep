# Сайт подготовки к экзамену

**Проекты.** На главной (`/`) — реестр проектов: под каждую изучаемую вещь (экзамен, предмет, курс)
свой проект со своими заданиями и прогрессом. Главная проекта — `/projects/<id>`, задание — `/tasks/<id>`.
В сайдбаре: «Подготовка» ведёт к реестру, название проекта — на главную проекта.
В админке: `/admin` — проекты (создать, переименовать, порядок, удалить каскадом со всем содержимым),
`/admin/projects/<id>` — задания проекта, `/admin/tasks/<id>` — содержимое задания.

Слева — задания проекта с прогрессом (кольцо 0–3), внутри задания три вкладки:
теория, задачи и тренировка:
- **Задачи** — примеры с разбором: условие и объяснение решения под катом («Показать решение»), без проверки
  ответа (предполагается, что человек ещё не умеет решать). Кнопка «Разобрал».
- **Тренировка** — самостоятельное решение: поле ответа и проверка; необязательное объяснение под катом.
  Верный ответ фиксируется на сервере (`problems.solved`), и кнопка «Завершить тренировку» заблокирована,
  пока не решены все задачи с заданным ответом (бэкенд тоже отвечает 409). Смена правильного ответа в админке
  сбрасывает фиксацию у этой задачи.
Теория разбита на главы: mind map + аккордеон, галочка «Прочитал» на главу;
теория зачитывается автоматически, когда прочитаны все главы.
Связи глав на карте задаются в админке (селект «связь» у каждой главы, NULL = центр);
клик по блоку карты открывает текст главы в модалке.
Тёмная/светлая тема, переключатель в шапке. UI по макету из Claude Design
(«Подготовка к экзамену.dc.html»).

## Запуск в Docker (проще всего)

```sh
docker compose up -d --build
```

Сайт: http://localhost:3000 · Админка: http://localhost:3000/admin.
Пароль админки: `ADMIN_PASSWORD=секрет docker compose up -d` (по умолчанию `admin`).
БД и загруженные картинки лежат в томах `db` и `uploads` и переживают перезапуск.
Создать демо-проект «ЕГЭ: математика (демо)» с 19 темами: `docker compose exec backend python seed_demo.py`
(пересоздаёт только сам демо-проект, остальные проекты не трогает).
Остановить: `docker compose down` (тома сохраняются; `down -v` — удалить и данные).

## Запуск без Docker (для разработки)

Бэкенд (FastAPI + SQLite, порт 8008):

```sh
cd backend
python3 -m venv venv && venv/bin/pip install -r requirements.txt   # один раз
venv/bin/uvicorn app:app --reload --port 8008
```

Бэкенд запускается вручную (не через preview/launch.json): песочница превью в Claude Code
не может читать файлы под ~/Documents для python-процессов, поэтому в launch.json только фронтенд.

Фронтенд (Next.js, порт 3000):

```sh
cd frontend
npm install        # один раз
npm run dev
```

Сайт: http://localhost:3000 · Админка: http://localhost:3000/admin

Пароль админки — переменная окружения `ADMIN_PASSWORD` у бэкенда (по умолчанию `admin`).
Имя пользователя в Basic-auth не проверяется.

## Устройство

- `backend/app.py` — всё API; SQLite-файл `backend/ege.db` создаётся пустым при первом старте.
  БД, созданные до появления проектов, при старте мигрируют: все их задания попадают в проект
  «Подготовка к экзамену».
- `backend/seed_demo.py` — демо-проект с контентом по 19 темам из макета (пересоздаёт только себя).
- `backend/test_api.py` — самопроверка: `venv/bin/pip install httpx && venv/bin/python test_api.py`
  (`httpx` нужен только тестам, поэтому его нет в `requirements.txt`).
- Контент — markdown c LaTeX-формулами (KaTeX): `$...$` — инлайн, `$$` на отдельных строках — блок.
  Работает в теории, задачах, тренировке, модалке карты и превью админки.
- У задачи два текстовых поля: `explanation_md` — разбор решения (под катом, и у задач, и у тренировки) и
  `solution_md` — короткий правильный ответ, нужен только тренировке. Проверка на клиенте
  (регистр, пробелы и запятая/точка нормализуются).
- Главы теории — таблица `theory_sections` (флаг `read` прямо в строке — пользователь один);
  прогресс «теория» вычисляется на бэкенде, вручную не ставится.
- Картинки грузятся в админке, файл кладётся в `backend/static/uploads/`.
- Прогресс: по галочке на вкладку (теория/задачи/тренировка), задание завершено при трёх.
